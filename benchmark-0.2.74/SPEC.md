# Spec: DeepStrike Node SDK 0.2.74 Benchmark

## Objective

建立一套直接针对当前 `@deepstrike/sdk` 0.2.74 公开 Node 子路径的测评体系。

第一版要回答四类问题：

1. 新 SDK 的公开契约是否完整：root intent API 与 `providers`、`workflow`、`planes`、`memory`、`harness`、`os`、`advanced`、`runtime`、`evals` 子路径是否按 0.2.74 暴露正确的符号，并保持 root 不泄漏内部 machinery。
2. 新 API 的行为是否正确：Agent facade 的 run/stream/session/resume/interrupt、memory 边界、workflow 与 dynamic workflow、execution plane、harness/evals 都要用公开入口验证。
3. 新 SDK 的可验证性是否成立：ReplayProvider、dynamic workflow replay、session evidence 与 eval trace 能否让同一输入得到可比较的结果。
4. 同一份运行结果能否被保存、重放、比较，并作为 golden regression 基线。

评测默认不需要外部 LLM API。需要模型的场景通过 `ReplayProvider` 使用固定 fixture；真实 provider 作为显式的 live 模式扩展。

## Commands

```bash
# 构建当前 Node SDK
npm run build --prefix node

# 列出场景
node benchmark-0.2.74/cli/bench.mjs list

# 无 API key 的公开契约 + 行为测评
node benchmark-0.2.74/cli/bench.mjs contract-surface
node benchmark-0.2.74/cli/bench.mjs agent-facade
node benchmark-0.2.74/cli/bench.mjs workflow --compare

# 运行本地测试
npm test --prefix benchmark-0.2.74

# 保存或检查 golden
node benchmark-0.2.74/cli/bench.mjs workflow-scheduler --baseline-save
node benchmark-0.2.74/cli/bench.mjs workflow-scheduler --baseline-check
```

## Code Style

- ES modules only, no new runtime dependencies.
- SDK imports go through `core/sdk.mjs`; callers never guess a dist export path.
- Scenario code exposes deterministic `run({ sdk, variant })` and returns serializable metrics plus evidence.
- Metric values use `{ value, unit, mode, samples }`.
- Every scenario declares its SDK surfaces and contract IDs; errors include the scenario, variant, and surface that failed.

```js
export const workflowScheduler = {
  id: "workflow-scheduler",
  variants: ["weighted", "fifo"],
  async run({ sdk, variant }) {
    const outcome = await runWorkflowFixture({ sdk, policy: variant })
    return { mechanism: collectSchedulerMetrics(outcome) }
  },
}
```

## Testing Strategy

- **Unit tests:** metric aggregation, diff significance, golden tolerance, fixture handling.
- **Contract conformance:** load every 0.2.74 public barrel, assert required exports and root leakage rules, and report the contract IDs.
- **Facade behavior:** exercise root `createAgent` with `ReplayProvider`, `LocalExecutionPlane`, and `InMemorySessionLog`; check result status, session identity, evidence, stream, memory, and interruption boundaries.
- **Workflow behavior:** exercise `RuntimeRunner.runWorkflow` and `runDynamicWorkflow` with a deterministic host; check scheduler, limits, lifecycle, replay reuse, and mismatch behavior.
- **Execution and evaluation:** check a public execution plane, `harness` attempt loop/manifest surfaces, and `evals.evaluate` trace/result contracts.
- **Replay integration:** use recorded provider and dynamic workflow fixtures and verify stable output across runs.
- Live provider tests are opt-in and are not part of the default test command.

## Boundaries

- Always: use the 0.2.74 subpath exports; keep default runs deterministic; write JSON artifacts.
- Ask first: adding third-party dependencies, changing CI workflows, or committing live provider output.
- Never: commit `.env`, API keys, `node_modules`, `node/dist`, or unreviewed live traces.

## Success Criteria

- `node benchmark-0.2.74/cli/bench.mjs list` works without building or API credentials.
- `node benchmark-0.2.74/cli/bench.mjs contract-surface` passes all declared public barrel contracts.
- `node benchmark-0.2.74/cli/bench.mjs agent-facade` and `workflow --compare` complete on the current 0.2.74 SDK.
- `npm test --prefix benchmark-0.2.74` passes without network access.
- A replay fixture can be read for every sample generated by the runner.
- Golden save/check returns a non-zero exit code only when a metric exceeds its declared tolerance.
- The repository contains only the 0.2.74 benchmark tree after migration.
