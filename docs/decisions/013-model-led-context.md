# DEC-13：模型主导上下文

## 状态

已接受

## 日期

2026-11-13

## 背景

0.2.82 想让上下文管理更省、更可靠。每一项改动都在 DeepSeek（`deepseek-flash`）上做了实测：和基线跑同一批题，逐题配对比较。一共测了十项改动，结果清楚地分成两类。

**第一类：内核按规则、或者靠自己发起的调用，判断内容的意义**

| 改动 | 内核做了什么 | 结果 |
|---|---|---|
| 8.3 / 8.3b / 8.3c | 按缓存成本账决定压缩什么 | long-horizon 上从未显著变好；最多 30 题里有 6 题跑到轮数上限 |
| 8.4 | 压缩时请宿主让模型写摘要 | long-horizon 12/30 → 4/30，每答对一题的成本变成 5 倍 |
| 9.2 | 优先换出被笔记引用的结果；换出前推迟一轮并预告 | 叠加在笔记上没有收益，成本 +31% |
| 9.3 | 每轮诊断笔记，交给模型修 | 几乎没有触发，没有收益 |
| 9.4 整理 | 每个会话结束后，宿主跑一次"梦境"式整理，对账记忆 | multi-session 33/48 → 33/48，每答对一题的成本 +272% |

**第二类：模型通过工具决定什么重要，内核负责把它留住**

| 改动 | 模型做了什么 | 结果（配对） |
|---|---|---|
| 9.1 笔记 | 自己写、自己改笔记（主要是一条累计计数），内核保证它扛过压缩 | long-horizon 15/30 → 20/30，每答对一题的成本 −43%；ledger 25/30 → 30/30；multi-session 9/48 → 33/48，每答对一题的成本 −68% |
| 9.4 提升 | 用 `propose_memory` 提交值得跨任务保留的内容，之后的会话召回 | （即上面的 multi-session 结果） |

另外两个发现改变了测量方法本身：

- **协议 bug 比上下文策略的影响更大。** DeepSeek 把工具调用标记当文本输出，在三个变体里一共终止了 90 次运行中的 21 次；Ollama 的工具调用 id 每轮重复，终止了 14 次本地运行中的 11 次。两者都是 provider 层的 bug，现在都已修复，并有了共用的测试数据。两次都曾被误读为上下文策略的失败。
- **gate 量错了东西。** 0.2.81 的默认 gate 既不比正确率也不比成本，放行了 8.4。8.1 的配对 gate 要求成本"显著更低"，这条规则是给省钱类改动设计的：笔记让正确率提高了 17–50 个点，却在每个场景都因为这一条或那一条没通过。

## 决定

### 1. 内核不为管理上下文发起模型调用

模型只能通过 `CallProvider` 调用，而且只能作为 run 的一轮。内核不发出任何要求宿主用模型去摘要、评判、排序或整理上下文的 effect。值得保留什么，由模型用自己的工具（`note`、`memory`、`propose_memory`）决定。effect 的封闭集合由一个测试锁定，测试失败的提示会指向本文。

### 2. 模型决定什么重要，内核负责留住

内核只管机制：

- 把模型写的内容原样保留，任何压缩层都不碰笔记；
- 预算超了就拒绝这次写入，而不是替模型删；
- 记录来源（指向证据的 `derived_from` 边）；
- 把它渲染在模型看得到的地方。

内核不再加任何自己的语义层：不用规则摘要替代模型的理解，也不按"猜模型需要什么"去调整遗忘的顺序。

### 3. 机制要证明自己有用，否则删除

- 新机制先放在一个默认关闭的开关后面。
- 要成为默认，它必须在每个目标场景、30 对以上的配对实测里，让正确率或"每答对一题的加权成本"**显著变好**，并且两者都**不显著变差**。这就是 lab 的默认 gate（`deepstrike-lab gate`，对应 `DEFAULT_IMPROVE`、`DEFAULT_PAIRED`）。
- 没通过就删除：代码、开关、协议、测试、文档全部删掉，只在计划里留下实测数据。不留休眠开关。
- 附加的机制要和"没有它的配置"比，而不是和最初的基线比。整理 run 对"无记忆"能过，对"只开笔记"就过不了。

### 4. 用模型实测，看每答对一题的价钱

- 实测、配对、同一批题；10 对只能看方向，30 对才能下结论。
- 衡量标准是每答对一题的成本，不是 token 数，也不是每题成本。
- 读上下文实验的结果之前，先排除协议层面的干扰（标记泄漏、id 重复、tool call 丢失）。

## 考虑过的其他做法

### 没通过的机制保留在默认关闭的开关后面

这是 8.4 最初的处理方式。休眠开关仍然要在四个 SDK 里维护、写文档、写测试，还会诱使别人在没有证据的情况下把它打开，而当初正是证据让它被关掉的。

### 保持 8.1 的 gate 不变

那样会删掉笔记。笔记是这个项目测到的最大收益，却会因为一条为另一类改动设计的标准而被删。

### 把 gate 放宽成"不显著变差"

起草本决定时考虑过，最终否决：在 30 对的样本下，它会放行 8.3b（long-horizon 12/30 → 8/30）。要求"显著变好"，才让这条规则成为奥卡姆剃刀，而不是只进不出的棘轮。

## 后果

- 笔记默认开启（`notes_budget_tokens` = 600）。每个请求都带 `note` 工具（工具说明约 320 token）；模型写下笔记后，状态块里会出现 `notes:` 一段。用 `notesBudgetTokens: 0` / `notes_budget_tokens: 0` 关闭。要复现 0.2.82 之前行为的基线，必须显式关掉。
- gate 的默认标准是在看到 0.2.82 的数据之后改的。这一点记在本文和 `DEFAULT_PAIRED` 的注释里。新规则已用此前所有决定回测过：它否决 8.3、8.3b、8.4 和整理 run，接受笔记，和当时的决定一致。
- 本决定之前就存在的机制，如规则摘要、叙述折叠、按效用打分的归档，都还没有用这个标准测过。它们同样要接受这项检验，并不因为早就存在而豁免。
